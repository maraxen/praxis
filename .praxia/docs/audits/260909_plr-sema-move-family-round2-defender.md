## R2-C6 — **CONCEDED (must-fix)**, and the spec's own self-assessment of this rule is wrong too

The unsound direction is real and I can name the runtime path: a handler whose last statement is `ast.Raise` but which contains an earlier `ast.Return` passes `isinstance(handler.body[-1], ast.Raise)`, so its rollback assignment is **ignored**; but a `return` leaves the function normally, so the *caller* continues to later delegates. For this anchor that means `drop_resource`'s `:2146-2147` (`self._resource_pickup is None`) is read as `HELD` while the field is `None` — a false `SAFE` on the exact guard the increment claims. The unsafe shape is unnamed. That mis-assessment should be corrected in the same edit, because it is the reason the hole was not found by the document itself.

**Minimal fix.** One clause on condition 2: "…and the handler body contains no `ast.Return`, `ast.Break` or `ast.Continue` at any depth; otherwise it widens", plus the negative fixture in AC-17.3's condition-2 pair, plus the §17.15 item (3) correction.
