# Brainstorm: Visualizer transport shim and augmentation API for the praxis JupyterLite/PLR REPL refocus: design the Python-side transport seam, the augmentation API shape, CDN vendoring, the first concrete augmentation, and upstream-drift detection.

## Problem Frame
FIXED CONSTRAINTS (cannot change):
- Static site only. No Python HTTP server, no websocket server, no backend. GH Pages is a target, so no COOP/COEP guarantee and no custom headers.
- The renderer runs in the browser main thread (a DOM document); the Python kernel runs in a DedicatedWorkerGlobalScope. `js.window` does NOT exist in the kernel — this is already a confirmed live bug in web_serial_shim.py. So ANY design that assumes the kernel can touch the visualizer DOM directly is dead on arrival. There must be a worker->document boundary crossing.
- lib.js is consumed unmodified (5853 lines). Non-negotiable.
- PLR is a git submodule; the visualizer assets must be derived from it, not hand-copied.
- Renderer and serializer must come from the SAME PLR pin (payload schema differs across pins).
- Konva 8.4.3 must be vendored; unpkg is not reachable in CI-like sandboxes.

NEW EVIDENCE I just gathered by reading external/pylabrobot/pylabrobot/visualizer/visualizer.py at the pinned d9651e2 — this materially changes option (1):
- `send_command(event, data, wait_for_response=False)` is the SINGLE funnel. All four events plus `show_machine_tools` and `stop` go through it (lines 604, 623, 626, 649, 658, 681, 585).
- Everything upstream of that funnel is reusable and NOT socket-aware: `_serialize_with_methods` (or `_serialize_resource_tree`+`_build_method_registry` at 0.2.2), `_sanitize_floats`, `_assemble_command` (adds id/version/data/event), the did_assign/did_unassign/state_update callback registration in `__init__` (lines 140-151), and the state-update BATCHING machinery `_enqueue_state_update`/`_flush_state_updates` (668-682) which exists precisely so a 96-channel pickup is one message.
- The ONLY socket-coupled bits are: `setup()` -> `_run_ws_server()`+`_run_file_server()`; `has_connection()`/`websocket` property; `stop()`'s httpd shutdown; and — this is the trap — three callbacks reach `self.loop` (`asyncio.run_coroutine_threadsafe(fut, self.loop)` at 650 and 659, `self.loop.call_soon_threadsafe` at 666). `self._loop` is set ONLY inside `_run_ws_server`, so a subclass that overrides only send_command still explodes on the first resource assignment.
- The fix is small and I want it on the table: in Pyodide an asyncio event loop IS already running, so a subclass can set `self._loop = asyncio.get_event_loop()` and `self.setup_finished = True` in its own setup(), and then `run_coroutine_threadsafe`/`call_soon_threadsafe` degrade to single-thread `call_soon` and just work. That means the override set is: `setup`, `stop`, `has_connection`, `send_command` — four methods, none of which mention a serializer, so the 485KB-vs-164KB payload-schema divergence across pins is INVISIBLE to us.
- Also note `_detect_source_filename()` runs in `__init__` and tries ipynbname/jupyter_server/urllib against a live Jupyter REST API — in Pyodide we must pass `name=` explicitly to short-circuit it.

NEGOTIABLE:
- Whether we subclass at all vs. reimplement the ~40 lines of callback wiring.
- Where the renderer lives: same-document sibling element, nested iframe, separate browser tab/window, or a notebook output cell (anywidget).
- Whether the channel is one-way (Python -> canvas) or bidirectional.
- Whether augmentations are authored in Python, in JS, or both.
- Which PLR pin we target (d9651e2 / 0.2.2 / main) — 0.2.2 currently looks strongly favoured by the 3x payload shrink and the pylibftdi stub going away.
- How much of the visualizer's own UI chrome (machine tools, sidebar, export) we keep.

## Decision Log
- [REJECT] E — In-browser websocket polyfill (run upstream Visualizer completely unmodified): Superficially the lowest patch surface, but it relocates ALL drift exposure into a fake-socket library that must emulate websockets.asyncio.server.serve, an async context manager, ServerConnection.recv/send, and asyncio.exceptions semantics inside Pyodide's partial WebLoop — plus _run_ws_server spawns a threading.Thread and busy-waits on a threading.Lock (visualizer.py:468-475), which cannot work in a worker with no real threads. It also requires the `websockets` package to import successfully in Pyodide (HAS_WEBSOCKETS is currently False there). We would own a harder, less testable surface than the 4 methods we are trying to avoid overriding.
- [REJECT] F — Fork/vendor a praxis renderer (edit lib.js freely): Violates the stated success criterion directly. lib.js is 5853 lines and upstream is ACTIVELY developing it (32 commits in the recon delta; +39/-25 between 0.2.2 and main). A fork means every upstream visualizer improvement becomes a manual merge forever, in exchange for augmentation power we do not need — the spike proved a Konva overlay layer plus event-boundary wrapping already gives us drawing and interception without a single edited line.
- [MERGE] C — Transport-protocol reimplementation, no subclass: Rejected as the primary mechanism: it does not actually reduce drift exposure, it MOVES it from a public class shape to private module-level function names (_serialize_with_methods vs _serialize_resource_tree + _build_method_registry), which the spike proved is the surface that ALREADY changed between pins — exactly the wrong thing to depend on. Subclassing and never naming a serializer is strictly more drift-robust. But C's best idea is grafted wholesale: the `VisualizerTransport` Protocol with swappable implementations (broadcast-channel, recording, file-dump, null) becomes the injected collaborator of the subclass, which is what makes browserless testing (D4) possible at all.
- [DEFER] D — Monkeypatch pylabrobot.visualizer.Visualizer in place at bootstrap: Real value: copy-pasted upstream PLR docs examples (`vis = Visualizer(deck); await vis.setup()`) would just work, which matters a lot for a teaching REPL. But as the PRIMARY mechanism it is worse than a subclass: it makes the transport unmockable in pytest, gives a confusing traceback when it misfires, and means there is no way to opt out. Deferred as a thin, optional, one-line-at-bootstrap ALIAS layer on top of the subclass (`pylabrobot.visualizer.visualizer.Visualizer = BrowserVisualizer`) once BrowserVisualizer is proven — cheap then, dangerous now.
- [ACCEPT] Augmentation shape: adopt A1 + A2 + A3 as one three-layer API; defer A4: A1 (JS event middleware), A2 (Konva overlay + anchor helper) and A3 (Python side-channel events) are not competitors — they are the three segments of one pipeline (produce in Python -> intercept in JS -> draw on canvas), and all three were spike-verified. Critically, all three depend ONLY on things that did not change across three PLR pins: the 4-event protocol, the `stage`/`resources` script-scope globals, and Konva's own public API. None touches lib.js internals. A4 (bidirectional canvas->Python) is DEFERRED: it needs the kernel to accept unsolicited work while idle, re-opens the user-gesture constraint from 97a75988, and nothing in either spike tested it.
- [ACCEPT] Vendoring: V3 (generate AND commit, with CI `git diff --exit-code` gate); V4 pursued in parallel as a slow track: V2's gitignored output reproduces the EXACT failure already live in this repo: assets/jupyterlite/build/ contains only service-worker.js, so a clean clone serves a dead page. That is a demonstrated, not hypothetical, cost. V1 has no single source of truth and silently rots on a submodule bump. V3 gets both properties for the price of six generated files in review. V4 (upstream a transport hook to PyLabRobot) is the only structural fix and is cheap to start, but cannot be depended on for this sprint.
- [ACCEPT] Drift detection: D2 + D4 as blocking per-PR gates; D3 as nightly/opt-in; D1 rejected: D2 (assert-each-vis.js-anchor-matched-exactly-once at generate time) and D4 (browserless payload schema snapshot) are both free of a browser and free of network, catch the two failure modes that actually bite (socket glue moved; payload schema changed), and fail at generate/test time when a human is already looking. D3 (golden render) catches semantic breakage the other two miss but needs a browser, and the spike PROVED Playwright's chromium download is unreachable from a sandboxed environment — so it must be nightly with a pinned system Chrome path, never a per-PR blocker. D1 (sha256 of every upstream file) is rejected as pure noise: lib.js changed +39/-25 between 0.2.2 and main with byte-identical render results (396 shapes/220 resources/18 tree nodes), so it would have fired a false alarm on the single most important real-world bump.
