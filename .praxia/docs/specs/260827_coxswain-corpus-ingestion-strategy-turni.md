# Brainstorm: Coxswain corpus ingestion strategy: turning 91 chory-lab/plr-cookbook recipes + 20 heterogeneous real-world PyLabRobot-dependent repos into floor_gen/overlay_gen-shaped training material — source triage criteria, per-source-type extraction targets, in-surface vs out-of-surface vs future-phase mapping, integration point with the two existing generators (extend overlay_gen's miner / extend floor_gen's matrix / new third pipeline), and the unaddressed licensing+attribution question.

## Problem Frame
FIXED (cannot change in this session):

F1. The 13-verb phase-2 surface and the canonical tables (coxswain.plr.param_namespace, TOOL_SCHEMA) are locked. Any mined call must normalize INTO those shapes or be counted-and-excluded. Ingestion may not widen the surface.
F2. Import boundary (F2-rev2): training/* may import coxswain.plr.*; nothing in coxswain/, praxis.backend.*, or any browser bundle imports back into training/. New ingestion code lives under training/.
F3. Never execute or import third-party PLR-consumer code. Both miners are AST-only, pure stdlib + coxswain.plr. Cloned repos are read-only text. This is a security constraint, not a style preference — we are parsing arbitrary GitHub code.
F4. Supervision fields are DERIVED, never authored: missing_required via coxswain.plr.slot_derivation, unresolved_slots likewise. Any new pipeline inherits this. An ingestion path that hand-authors a supervision field is disqualified.
F5. Exclusions are counted with a recorded reason (MinedExclusion), never silently dropped. Auditability of what we chose not to use is part of the artifact.
F6. Determinism / replayability: content-hash teacher cache keyed (prompt_version, input_hash); same sha => byte-identical corpus; offline regenerate must work.
F7. external/pylabrobot is read-only vendored ground truth. New third-party clones live OUTSIDE the repo (~/projects/repos/) — we are not vendoring 20 repos into praxis.
F8. Teacher backend is currently BLOCKED (P2.5 blocker). Nothing may assume teacher calls are available today.

NEGOTIABLE (this is what we are actually deciding):
N1. Whether ingestion is a third pipeline, a miner extension, a matrix extension, or a composite.
N2. What the unit of extraction is — call, call-sequence, recipe, task-title, or an abstract task-type label.
N3. Whether NL comes from the teacher (paraphrase) or is harvested from the source (cookbook titles / annotations / docstrings / prose).
N4. Triage granularity: per-repo whole/skip, per-file, or per-call-site.
N5. Whether out-of-surface material trains a refusal/clarify behavior now, or is parked as future-phase seed.
N6. Licensing posture — permissive-only allowlist, fair-use-with-attribution, index-only-no-code, or per-source manual clearance.
N7. Whether the cookbook and the 20 repos share one pipeline at all, or are deliberately separated.

HIDDEN CONSTRAINTS I want on the record before divergence, because they will otherwise be discovered late:

H1. ASYMMETRY OF EVIDENCE. The cookbook is CI-execution-verified against pinned PLR 0.2.2, carries human-authored task-phrased titles, and has a machine-readable index. The 20 repos have NONE of those three properties. Any design that treats "the cookbook" and "a repo" as instances of one source type is quietly asserting an equivalence that the evidence does not support.

H2. THE COOKBOOK'S CENTER OF MASS IS OUT-OF-SURFACE. Of 18 chapters, the copilot's 13 verbs are concentrated in chs 4, 6, 8, 9 — roughly a quarter of the book. Chapters 10-18 (errors, state, SQLite, hardware quirks, logging, composition, simulation, custom labware, custom backends) are almost entirely outside the surface. So the cookbook's DOMINANT yield is out-of-surface material, and a design optimized for in-surface call harvesting will throw away most of the source's value. floor_gen currently has only a handful of out-of-surface cells and they are hand-authored — this is the gap the cookbook actually fills.

H3. THE TEACHER-BUDGET BLOCKER FLIPS THE ORDERING. Because the teacher is blocked, an offline-derivable deliverable (an index, a triage ledger, a mined-call table, a matrix diff) has strictly more value today than any NL-ification plan. A winning strategy should front-load the offline half and leave the teacher half as a downstream, cache-shaped stage.

H4. LEGAL ASYMMETRY IS ALREADY KNOWN AND ALREADY BAD. No LICENSE on the cookbook = all rights reserved by default. cheshire-drivers is AGPL. Neither is a "check later" item if the plan's core is "mine code from ~20 repos" — the licensing answer can invalidate the plan's premise, so it has to be decided in the same breath as the triage rule, not bolted on.

H5. CONTAMINATION RISK IS DIRECTIONAL. Bad in-surface data (a wrong param mapping from a hobby repo) poisons the parse adapter directly. Bad out-of-surface data mostly costs a wasted clarify example. So triage strictness should be asymmetric: strict for in-surface extraction, permissive for out-of-surface labels.

H6. ONE SOURCE IN THE POOL IS NOT A CORPUS AT ALL. GreenTilden/oolitic-plr is an LLM-for-PLR-codegen project and vanallenlab/agentic-ai-codebase is an LLM-agent-to-lab-automation bridge. Mining their generated/prompt material risks training on another model's output and on prompt scaffolding rather than on real protocols. That is a distinct rejection class from "low activity."

Its outputs are inputs to floor_gen (a reviewable matrix-diff), to overlay_gen (new mined-call source roots + harvested anchor NL), to coxswain/tests/fixtures/parsed_calls (golden fixtures), and to a held/ directory the corpus assembler does not read. This is why candidate C's "third pipeline" is deferred and candidate A's "one more source root" is insufficient: the new work is source ADMISSION, not example GENERATION, and admission has no home in either existing generator.

THE THREE AXES (the forcing beat's finding, made structural). The killed version of E used one "trust" scalar. The winner keeps three independent axes that cross-cut:
  (i) LICENSE TIER — caps WHAT MAY FLOW. Verified mechanically, not assumed.
  (ii) EXTRACTABILITY — decides WHICH PARSER RUNS (recipes.yml index / .qmd chapter / .ipynb / plain .py).
  (iii) MEASURED YIELD + REALISM — decides WHERE TEACHER BUDGET GOES.
A source's profile on one axis says nothing about the others. The cookbook is high extractability, tier-0 license (no LICENSE file), and unproven realism (teaching artifact: round volumes, a plate named "plate"). ngs_library_prep inverts that. Any design collapsing these gives a wrong verdict on every mixed-profile source, which is most of them.

CONCRETE SHAPE — `training/ingest/`, stdlib + coxswain.plr only, AST-only, never executes third-party code (F3), lives under training/ (F2):
  - `sources.py` — committed SourceRegistry: 21 rows (cookbook + 20 repos). Per row: repo URL, local clone path under ~/projects/repos/ (NOT vendored, per F7), pinned commit SHA, SPDX id or NONE, derived license_tier, genre (TRIAGE-3), extractor kind, and an admission_argument string that is null for rejected sources (TRIAGE-5 reject-by-default).
  - `licenses.py` — mechanical verification: read LICENSE at the pinned SHA, map to SPDX, derive tier. No license file => tier 0. AGPL/GPL => tier 0 (hard cap; cheshire-drivers). Ambiguous => tier 0.
  - `recon.py` — the offline measurement pass, run over EVERY source: in-surface verb hits, out-of-surface hits, UNKNOWN-verb hits, layer distance (direct `lh.<verb>` call vs own wrapper — TRIAGE-4), files parsed, parse failures, and observed value formats (ORTHOGONAL-6's free check on floor_gen/value_formats.py's hand-pinned conventions). Output: recon.jsonl + report. This is what makes triage a measurement, not a vibe.
  - `cookbook.py` — two parsers. (a) recipes.yml -> 91 (title, path, chapter, apis) rows. (b) .qmd chapters -> recipe fences (`::: {.recipe}`), `## Title {#anchor}` matched back to recipes.yml paths, ```{python} cells, inline `# <n>` annotation glosses paired to their call, and the collapsed setup cell's labware BINDINGS (UNIT-5). VERIFIED IMPLEMENTATION REQUIREMENT: cells contain top-level `await`; plain ast.parse() raises SyntaxError, so each cell body must be wrapped in a synthetic `async def` before parsing — the existing .ipynb miner only strips %/! magics and will break here.
  - `audit.py` — the drift detector (ORTHOGONAL-2), FIRST DELIVERABLE. Diffs the cookbook's ~450 named APIs against TOOL_SCHEMA + PARAM_NAMESPACE. Reports every difference with BOTH readings — "our hand-derived table is wrong" vs "the API moved between cookbook-pinned 0.2.2 and vendored HEAD dd79c4c89" — and NEVER auto-patches a table. Specifically stress-tests the four recorded phantom verbs (mix, blow_out, touch_tip, dispense_to_waste) against the cookbook's Mix recipe.
  - `route.py` — ROUTE-1/2/4/5. Three-way in-surface / out-of-surface / HOLD, plus the UNKNOWN bucket that does not exist today (current _KNOWN_VERBS = TOOL_SCHEMA | NON_SURFACE_VERB_REASONS makes every other verb silently invisible — safe for two PLR-native sources, unsafe for 21). Cookbook routing declared as committed per-chapter DATA (18 rows), in the spirit of HARDWARE_CONTEXT_ONLY_NOTEBOOKS. Routing is a re-derivable VIEW over extraction, so a phase-3 surface widening re-routes held material without re-mining or re-licensing.
  - `gap.py` — coverage-gap report against the EXISTING corpus: which of the 43 matrix cells are thin, which verbs have few distinct mined param shapes, what is absent. This is ORTHOGONAL-7 promoted to a gate.
  - `provenance.py` — F9 row schema (repo, SHA, path, in-file origin, license verdict, tier, routing reason) + the generated SOURCES manifest (LICENSE-5), which doubles as the retraction index.

LICENSE LADDER (answers N6, binding on every output):
  TIER 0 FACTS-ONLY — API names, verb frequencies, param names, task vocabulary, counts. Available for ANY source regardless of license, including unlicensed and AGPL. Creates no derivative work.
  TIER 1 STRUCTURE — normalized MinedCall rows with literal param values, symbolic refs, call ordering. Verified-permissive MIT/BSD/Apache-2.0 only.
  TIER 2 EXPRESSION — verbatim harvested NL (titles, `# <n>` annotations, docstrings) used as anchor utterances. Verified-permissive OR explicit written permission only.
  TRACKED ACTION: open an issue on chory-lab/plr-cookbook requesting an explicit license. It costs one issue and promotes the pool's best source from tier 0 to tier 2. Written into the plan with a date because unwritten human actions never happen.
  ACCEPTANCE CRITERION (LICENSE-6): the plan must still deliver value if EVERY third-party source lands at tier 0 — external/pylabrobot (MIT, vendored) and praxis's own protocols remain fully usable.

NL POLICY (answers N3): harvest-then-paraphrase (NL-2). The source's own human NL is the ANCHOR; teacher budget buys only register-shifted VARIANTS. The variant prompt's declared job is REGISTER TRANSFER (NL-4) — anchor in documentation register ("Rotate a plate"), variants in user register including underspecified ones — with the register policy pinned in versions.py so the corpus records which policy produced which rows.
